# CIEL — Манас-интеллект (Android + облачный backend)

Это исходный проект мобильной версии на основе загруженного `CIEL.py` и `Ciel.ico`. Сохранены название, тёмная янтарная палитра, роль помощницы, чат, история, отправка фото, голосовой ввод и озвучивание ответов. Редактор файлов из настольной программы не перенесён в мобильный клиент.

## Важное про автономную работу

Телефон общается с облачным backend, а тот — с облачной моделью через OpenAI-compatible Chat Completions API. Компьютер и Ollama не нужны. Сам backend не содержит саму большую языковую модель: для этого проекта нужен API-провайдер с поддержкой Chat Completions и изображений (или собственная облачная GPU-модель с совместимым API). Ключ провайдера хранится только на сервере.

## 1. Разверните backend

Нужен Python 3.11+ и HTTPS-хостинг с постоянным диском (например, VPS; на PaaS проверьте поддержку persistent disk). В папке `backend`:

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS:
source .venv/bin/activate
pip install -r requirements.txt
```

Установите переменные окружения:

- `LLM_BASE_URL` — базовый URL OpenAI-compatible API, например `https://api.openai.com/v1`.
- `LLM_API_KEY` — ключ выбранного провайдера.
- `LLM_MODEL` — модель, поддерживающая чат и изображения, например `gpt-4o-mini` у провайдера OpenAI.
- `CIEL_ACCESS_TOKEN` — длинный случайный секрет для доступа приложения к backend.
- `DATABASE_PATH` — путь к SQLite на постоянном диске, например `/data/ciel.sqlite3`.

Пример запуска локально для проверки (не для публичного интернета):

```bash
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_API_KEY="вставьте_ключ_провайдера"
export LLM_MODEL="gpt-4o-mini"
export CIEL_ACCESS_TOKEN="сгенерируйте-длинный-случайный-секрет"
export DATABASE_PATH="./ciel.sqlite3"
uvicorn main:app --host 0.0.0.0 --port 8000
```

Для размещения в интернете разверните папку `backend` на сервере с HTTPS, задайте те же переменные в панели хостинга и подключите постоянный диск. Не открывайте HTTP-порт напрямую в интернет; используйте HTTPS reverse proxy или хостинг с TLS. Endpoint `/health` проверяет доступность приложения, но не тестирует провайдера.

## 2. Соберите Android-приложение

1. Установите Android Studio (актуальную стабильную версию) и Android SDK.
2. Откройте папку `android` как проект.
3. Дождитесь Gradle Sync. Если Android Studio предложит установить нужную версию SDK, согласитесь.
4. Запустите приложение на Android-телефоне или эмуляторе.
5. Откройте ⚙ Настройки и заполните:
   - **URL сервера**: адрес backend с `https://`, например `https://ciel.example.com` (без `/` в конце).
   - **Токен доступа**: значение `CIEL_ACCESS_TOKEN`.
6. Проверьте отправку сообщения, голосовой ввод и прикрепление фото.
7. Для APK: **Build → Build Bundle(s) / APK(s) → Build APK(s)**. Debug APK будет в `android/app/build/outputs/apk/debug/app-debug.apk`.
8. Для публикации создайте собственный signing key и соберите подписанный release APK/AAB через **Build → Generate Signed Bundle / APK**.

## 3. Что уже реализовано

- Kotlin + Jetpack Compose интерфейс с названием CIEL и исходной иконкой.
- Чат и серверная история диалогов (SQLite).
- Отправка фотографий в модель с поддержкой vision.
- Голосовой ввод Android Speech Recognizer и озвучивание Android Text-to-Speech.
- Переключение янтарной / океанской / фиолетовой / светлой / тёмной темы.
- Настройка адреса backend и токена в приложении.
- Backend использует инструкцию личности из `CIEL.py` и поддерживает OpenAI-compatible API.

## 4. Ограничения и безопасность

- История хранится на сервере; в этом стартовом проекте используется один общий секрет доступа, а не система отдельных пользовательских аккаунтов. Не раздавайте APK с одинаковым секретом публично. Для публичного релиза добавьте регистрацию, индивидуальные токены, rate limiting и политику удаления данных.
- Для доступа из любого места обязателен интернет и работающий облачный backend и LLM API. Бесплатность/доступность модели зависит от выбранного провайдера.
- Изображения кодируются для запроса к модели, но сами файлы не сохраняются в базе истории.
- Облачный провайдер может обрабатывать текст и изображения согласно собственным условиям и политике хранения.
- Настольная функция «Изменить код» намеренно не перенесена: безопасный мобильный аналог потребовал бы отдельного проектирования и подтверждений.

### Render.com (пример развёртывания)

В корне проекта лежит `render.yaml` как стартовый шаблон. При подключении репозитория в Render проверьте, что создан persistent disk в `/data`, а переменные `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и `CIEL_ACCESS_TOKEN` заданы верно. Если Render сам сгенерировал `CIEL_ACCESS_TOKEN`, скопируйте его значение из панели Environment в настройки приложения. Платформа и постоянный диск могут быть платными.
